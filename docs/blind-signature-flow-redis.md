# Сліпі підписи: sequence-діаграма з Redis

Доповнення до `docs/blind-signature-flow.md` — той самий протокол сліпих підписів, але з роллю Redis у потоці голосування. Redis використовується лише як службовий шар: блокування, анонімні лічильники, тимчасові квитанції та кеш — жодного зберігання токенів або вибору виборця.

---

## Sequence-діаграма (voting) з Redis

```
   Виборець (браузер)    Сервер (NestJS)                   Redis                   Postgres
        │  генерує T, r                  │                               │                              │
        │  blinded = T·r^e mod n                │                               │                              │
        │  tokenHash = HMAC(T)                  │                               │                              │
        │                                       │                               │                              │
        │  POST /votings/:id/sign               │                               │                              │
        │  {tokenHash, blinded, options}        │                               │                              │
        │───────────────────────────────────────▶                               │                              │
        │                                       │  право на голос ✓ │                              │
        │                                       │──────────────────────────────────────────────────────────────▶
        │                                       │  PendingBallot{tokenHash,     │                              │
        │                                       │    userId, selections}        │                              │
        │                                       │──────────────────────────────────────────────────────────────▶
        │                                       │  VoteParticipation.sigUsed=✓  │                              │
        │                                       │──────────────────────────────────────────────────────────────▶
        │                                       │  blindSig = blinded^d mod n   │                              │
        │  ◀── blindSig ────────────────────────│                               │                              │
        │  sig = blindSig · r⁻¹ mod n           │                               │                              │
        │  (= T^d mod n)                        │                               │                              │
        │                                       │                               │                              │
        │  POST /votings/:id/vote               │                               │                              │
        │  {token, signature, options}          │                               │                              │
        │───────────────────────────────────────▶                               │                              │
        │                                       │  verify: sig^e ≡ T mod n      │                              │
        │                                       │  acquireLock(vote_lock, 15s)  │                              │
        │                                       │───────────────────────────────▶                              │
        │                                       │                               │  lock granted (NX/EX)        │
        │                                       │  Ballot{blindSignature=sig}   │                              │
        │                                       │    (без userId)            │                              │
        │                                       │──────────────────────────────────────────────────────────────▶
        │                                       │  забрано PendingBallot │                              │
        │                                       │──────────────────────────────────────────────────────────────▶
        │                                       │  performVote: INCR            │                              │
        │                                       │───────────────────────────────▶                              │
        │                                       │                               │  voting:{id}:total_votes     │
        │                                       │                               │  global:vote_count,          │
        │                                       │                               │  global:trends               │
        │                                       │  setTemporaryReceipts         │                              │
        │                                       │    (TTL 300s)                 │                              │
        │                                       │───────────────────────────────▶                              │
        │                                       │                               │  vote_receipts (TTL 300s)    │
        │                                       │  del results:snapshot         │                              │
        │                                       │───────────────────────────────▶                              │
        │                                       │  releaseLock                  │                              │
        │                                       │───────────────────────────────▶                              │
        │  ◀── receipts ────────────────────────│                               │                              │
```

> **Зверніть увагу:** сервер ніколи не бачить пару `(T, sig)` разом з ідентичністю. У кроці `sign` є `blinded` + ідентичність; у кроці `vote` — `sig` без ідентичності. Зв'язку немає.

> **Redis і анонімність:** Redis містить лише анонімні лічильники (`voting:{id}:total_votes`, `global:vote_count`, `global:trends`) без ідентичності, короткоживучі блокування `vote_lock` (TTL) та тимчасові квитанції `vote_receipts` (TTL 300 с — хеші бюлетенів, а не вибір). Жоден ключ не зв'язує виборця з його голосом — повний дамп Redis не дозволяє визначити, хто і як проголосував.

---

## Що саме зберігає Redis

| Ключ / префікс | Вміст | Час життя | Ідентичність |
|---|---|---|---|
| `vote_lock:{votingId}:{userId}` | маркер блокування (антиповторне голосування) | TTL 15 с | так, але без вмісту голосу |
| `voting:{votingId}:total_votes` | лічильник голосів | постійно | ні |
| `global:vote_count` | загальний лічильник | постійно | ні |
| `global:trends` | голоси за годину (hash) | постійно | ні |
| `vote_receipts:{votingId}:{userId}` | квитанції — хеші бюлетенів | TTL 300 с | так, але не вибір |
| `results:snapshot:{votingId}` | агрегатний снапшот результатів | TTL 7200 с | ні |
| `audit_seq:*`, `audit_ver:*` | лічильники аудиту | постійно | ні |

Інваріант: жоден ключ не зберігає пару «користувач → вибір». Вибір голосу живе лише в анонімній таблиці `Ballot` (без `userId`).

---

## Модель загроз: Redis

**Що захищає схема:**
- зламана Redis не компрометує анонімність голосування: у ній лише анонімні лічильники (`voting:{id}:total_votes`, `global:vote_count`, `global:trends`), короткоживучі блокування `vote_lock` (TTL) і тимчасові квитанції (TTL 300 с) — жоден ключ не пов'язує ідентичність виборця з його голосом;
- токенів у Redis немає — лише лічильники; навіть повний дамп не деанонімізує голос;
- `Ballot` / `SurveyBallot` не містять `userId` — канонічний запис голосу анонімний незалежно від стану Redis.

**Що схема НЕ захищає (чесно):**
- `VoteParticipation` (і `PendingBallot`) зберігають факт «користувач отримав підпис для voting N» — сервер знає, хто голосував, але не *як*;
- `vote_receipts` тимчасово (TTL 300 с) пов'язує `userId` з хешами бюлетенів — квитанція потрібна виборцю для перевірки свого голосу, але вона містить хеш, а не вибір;
- якщо приватний ключ RSA витіче — підписи можна підробляти (зберігання ключа — критичне).
